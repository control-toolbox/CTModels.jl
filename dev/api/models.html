CTModels.Models [Module] ​

CTModels.Models Module
julia
Models

Immutable optimal control problem model type and all its accessor methods.

Provides AbstractModel, struct Model (parametric over time dependence and component types), and all reader functions that operate on a built Model.

Organisation

  • hamiltonians.jl: the pseudo-Hamiltonian and Hamiltonian getters

  • constraint_terms.jl: the constraint terms adjoined to them, by label

  • model.jl: AbstractModel, Model struct, and all accessor functions (CTModels.Components.state, CTModels.Components.control, CTModels.Components.variable, CTModels.Components.times, CTModels.Components.objective, CTModels.Models.constraints, CTModels.Models.dynamics, CTModels.Models.definition)

Public API

The following functions are exported and accessible as CTModels.function_name():

  • Types: CTModels.Models.AbstractModel, CTModels.Models.Model

  • Time dependence predicates: is_autonomous, is_nonautonomous

  • Variable / control presence predicates: is_variable, is_nonvariable, is_control_free, has_variable, has_control, has_abstract_definition, is_abstractly_defined

  • Component field accessors: CTModels.Components.state, CTModels.Components.control, CTModels.Components.variable, CTModels.Components.times, CTModels.Components.objective, CTModels.Models.constraints, CTModels.Models.dynamics, CTModels.Models.definition

  • Named accessors on state/control/variable: CTModels.Models.state_name, CTModels.Models.state_components, CTModels.Models.state_dimension, CTModels.Models.control_name, CTModels.Models.control_components, CTModels.Models.control_dimension, CTModels.Models.variable_name, CTModels.Models.variable_components, CTModels.Models.variable_dimension

  • ExaModels builder: CTModels.Models.get_build_examodel

  • Constraints helpers: CTModels.Models.isempty_constraints, CTModels.Models.constraint

  • Hamiltonians: pseudo_hamiltonian, hamiltonian (methods of the CTBase.Data generic functions)

Dependencies

Depends on Components for foundational types and low-level accessor functions.

See also: CTModels.Components, CTModels.Building, CTModels.Solutions, CTModels.Init.

AbstractModel [Abstract Type] ​

CTModels.Models.AbstractModel Type
julia
abstract type AbstractModel

Abstract base type for optimal control problem models.

Subtypes represent either a fully built immutable model (CTModels.Models.Model) or a mutable model under construction (PreModel).

Model [Struct] ​

CTModels.Models.Model Type
julia
struct Model{TD<:CTBase.Traits.TimeDependence, TimesModelType<:CTModels.Components.AbstractTimesModel, StateModelType<:CTModels.Components.AbstractStateModel, ControlModelType<:CTModels.Components.AbstractControlModel, VariableModelType<:CTModels.Components.AbstractVariableModel, DynamicsModelType<:Function, ObjectiveModelType<:CTModels.Components.AbstractObjectiveModel, ConstraintsModelType<:CTModels.Components.AbstractConstraintsModel, DefinitionType<:CTModels.Components.AbstractDefinition, BuildExaModelType<:Union{Nothing, Function}} <: CTModels.Models.AbstractModel

Immutable optimal control problem model containing all problem components.

A Model is created from a PreModel once all required fields have been set. It is parameterised by the time dependence type (Autonomous or NonAutonomous) and the types of all its components.

Fields

  • times::TimesModelType: Initial and final time specification.

  • state::StateModelType: State variable structure (name, components).

  • control::ControlModelType: Control variable structure (name, components).

  • variable::VariableModelType: Optimisation variable structure (may be empty).

  • dynamics::DynamicsModelType: System dynamics function (t, x, u, v) -> ẋ.

  • objective::ObjectiveModelType: Cost functional (Mayer, Lagrange, or Bolza).

  • constraints::ConstraintsModelType: All problem constraints.

  • definition::DefinitionType: Original symbolic definition of the problem.

  • build_examodel::BuildExaModelType: Optional ExaModels builder function.

constraint [Function] ​

CTModels.Models.constraint Function
julia
constraint(
    model::CTModels.Models.Model,
    label::Symbol
) -> Tuple{Symbol, Any, Any, Any}

Get a labelled constraint from the model, as a tuple (type, f, lb, ub).

type is the kind of the constraint (:path, :boundary, :state, :control or :variable), f an out-of-place function evaluating the constrained quantity, and lb, ub its bounds. f is a named functor, so it prints as such:

typefCall
:pathCTModels.Models.SubPathConstraintf(t, x, u, v)
:boundaryCTModels.Models.SubBoundaryConstraintf(x0, xf, v)
:stateCTModels.Models.BoxProjection{:state}f(t, x, u, v)
:controlCTModels.Models.BoxProjection{:control}f(t, x, u, v)
:variableCTModels.Models.BoxProjection{:variable}f(x0, xf, v)

A constraint of dimension one gives a scalar value and scalar bounds (1-D is a scalar).

Arguments

  • model::Model: The optimal control problem.

  • label::Symbol: The constraint label.

Returns

  • Tuple: (type, f, lb, ub).

Throws

  • CTBase.Exceptions.IncorrectArgument: if no constraint of the model has the label label.

See also: CTModels.Models.constraints, CTModels.Components.path_constraints_nl.

constraint_rows [Function] ​

CTModels.Models.constraint_rows Function
julia
constraint_rows(
    model::CTModels.Models.Model,
    label::Symbol
) -> Tuple{Symbol, Vector{Int64}}

Return the kind of the constraint labelled label and the rows it occupies, (kind, rows).

  • kind is :path or :boundary for a nonlinear constraint, and rows its rows in the stacked constraint vector (path_constraints_nl(model), boundary_constraints_nl(model)), in increasing order. The rows of a label are contiguous, in the order of declaration.

  • kind is :state, :control or :variable for a box, and rows the components it bounds. A box label is any of the aliases of a deduplicated box declaration.

This is the layout of the duals of the solution: the dual of a path or boundary label is stored in the rows rows of the stacked dual, the dual of a box label in the components rows of the box duals.

Throws

  • CTBase.Exceptions.IncorrectArgument: if label is not a constraint of the model.

See also: CTModels.Models.constraint, CTModels.Solutions.dual.

hamiltonian [Function] ​

CTBase.Data.hamiltonian Function
julia
hamiltonian(object, args...; kwargs...)

Return the Hamiltonian of object, an CTBase.Data.AbstractHamiltonian.

This generic function has no method in CTBase: it is the single owner of the name, and each package that builds a Hamiltonian adds its own methods to it (for instance the Hamiltonian of an optimal control problem, or the one a Hamiltonian flow integrates), so that every method is reached through one function. It is the counterpart of CTBase.Data.pseudo_hamiltonian.

See also: CTBase.Data.AbstractHamiltonian, CTBase.Data.pseudo_hamiltonian.

See also: CTBase.Data.control_law, CTBase.Data.multiplier.

julia
pseudo_hamiltonian(
    ocp::CTModels.Models.Model;
    p0::Real,
    constraints
) -> Union{CTBase.Data.ConstrainedPseudoHamiltonian, CTBase.Data.PseudoHamiltonian}

Return the pseudo-Hamiltonian of the optimal control problem ocp,

where f is the dynamics and ℓ the Lagrange cost (absent for a Mayer problem). It does not depend on any control law. The pseudo-Hamiltonian is always maximised (ct-conventions SGN4): only the sign of p⁰ depends on the criterion.

With constraints, the labelled path constraints, state boxes or control boxes are adjoined with their multipliers μ, an explicit argument like the control:

where each constraint lb ≤ c ≤ ub enters on its active side, g ≥ 0, with its multiplier in the sign convention of the duals of a solution (ct-conventions SGN2, SGN3), component by component:

Bounds of the componentTermMultiplier y
lower only, lb ≤ cy (c − lb)y ≥ 0
upper only, c ≤ uby (ub − c)y ≥ 0
both, or c = lb = ub−y (c − b), b = ub if y > 0, lb otherwisesigned

For a constraint with two bounds the active side is read on the sign of y; the term is continuous at y = 0. Constraints not listed are inactive. The partial derivatives of H in x and p, at fixed u and μ (see CTBase.Data.freeze_multiplier), give the extremals of the maximum principle.

Arguments

  • ocp::Model: an optimal control problem with a control.

  • p0::Real: the multiplier of the cost; -1 for :min and +1 for :max by default (normal case), 0 for the abnormal case. Its sign must agree with the criterion.

  • constraints: a label, or a tuple or vector of labels, of path constraints, state boxes or control boxes of ocp; none by default. The bounds of a box are the effective bounds of its components, intersected over all the labels that bound them: a label written x₁(t) ≥ 0 gives a two-sided term, with a signed multiplier, if another label bounds x₁ above.

Returns

  • Without constraints, a CTBase.Data.PseudoHamiltonian, callable with its natural signature, H̃(x, p, u), H̃(t, x, p, u), H̃(x, p, u, v) or H̃(t, x, p, u, v), and with the uniform signature H̃(t, x, p, u, v).

  • With constraints, a CTBase.Data.ConstrainedPseudoHamiltonian, callable as H([t, ]x, p, u, μ[, v]) and H(t, x, p, u, μ, v), where μ stacks the multipliers of the labels in the order given, each with the components of its constraint.

A one-dimensional state, control, variable or multiplier is a number. A batched state (a Matrix, one column per point, as in CTFlows batched flows) comes with batched arguments, a quantity of dimension d being a d × batch matrix; the value is the sum over the points, and the functions of the model must be written on the columns.

Throws

  • CTBase.Exceptions.PreconditionError: if ocp is control-free (use CTBase.Data.hamiltonian instead).

  • CTBase.Exceptions.IncorrectArgument: if the sign of p0 contradicts the criterion; if a label is unknown, given twice, or names a boundary constraint or a variable box, which do not enter the Hamiltonian; if two labels bound the same component of the state or of the control; and, at the call, if μ does not have the dimension of the constraints.

Example

julia
julia> H̃ = CTModels.Models.pseudo_hamiltonian(ocp)    # ẋ = u, ∫ x² → min, x(t) ≥ 0.1, (x_con)

julia> H̃(1.0, 2.0, 0.5)                              # p·u − x²
0.0

julia> CTModels.Models.pseudo_hamiltonian(ocp; p0=0)(1.0, 2.0, 0.5)   # abnormal: p·u
1.0

julia> H = CTModels.Models.pseudo_hamiltonian(ocp; constraints=:x_con);

julia> H(1.0, 2.0, 0.5, 3.0)                         # p·u − x² + μ (x − 0.1)
2.7

See also: CTBase.Data.hamiltonian, CTModels.Models.PseudoHamiltonianFunction, CTModels.Models.ConstrainedPseudoHamiltonianFunction.
