Plotting architecture ​

This page is for contributors who change what the solution figure contains. To use the plots, see Plotting.

Three layers ​

The figure is described once, independently of any plotting package, and rendered by two thin backends:

text
Solution ── CTModels.PlotCase.build_figure ──► CTBase.Plotting.Figure ──► render
             (core, no plotting dependency)     (backend-free IR)          │
                                                                           ├─ CTModelsPlots → Plots.Plot
                                                                           └─ CTModelsMakie → Makie.Figure

  • CTModels.PlotCase (core module) knows optimal control: which groups exist (state, costate, control, path constraints, duals), how to sample them from a Solution, which reference lines to add (box bounds, initial and final times), and how to arrange the panels for layout=:split and layout=:group. It has no dependency on Plots or Makie.

  • CTBase.Plotting owns the figure IR (Figure, panels, layout nodes) and its renderers, shared by every control-toolbox package that plots. See the Plotting Engine guide of the CTBase documentation.

  • CTModelsPlots / CTModelsMakie (extensions) only add the Plots.plot / Makie.plot methods: they split the keywords, call build_figure, and pass the result to the PlotsBackend or MakieBackend renderer.

Because both backends render the same IR, they stay at feature parity by construction: a new panel or decoration added in PlotCase appears in both.

Building a figure without a backend ​

build_figure is callable from the core, which makes the content of a figure testable without loading a plotting package:

julia
using CTModels

pre = CTModels.PreModel()
CTModels.variable!(pre, 0)
CTModels.time!(pre; t0=0.0, tf=1.0)
CTModels.state!(pre, 2)
CTModels.control!(pre, 1)
CTModels.dynamics!(pre, (r, t, x, u, v) -> (r[1] = x[2]; r[2] = u; nothing))
CTModels.objective!(pre, :min; lagrange=(t, x, u, v) -> u^2)
CTModels.constraint!(pre, :control; rg=1:1, lb=[-1.0], ub=[1.0], label=:u_box)
CTModels.time_dependence!(pre; autonomous=true)
ocp = CTModels.build(pre)

N = 21
T = collect(range(0.0, 1.0; length=N))
sol = CTModels.build_solution(ocp, T, hcat(T, ones(N)), ones(N, 1), Float64[], zeros(N, 2);
    objective=1.0, successful=true)

fig = CTModels.PlotCase.build_figure(sol, :state, :control; layout=:group)
julia
julia> typeof(fig)
CTBase.Plotting.Figure

What is plotted ​

build_figure draws up to five groups, selected by the description symbols (:state, :costate, :control, :path, :dual) and hidden by a *_style=:none keyword. In layout=:split, they are arranged in three blocks:

text
(state | costate)          one cell per component, paired column by column
control                    full width
constraint rows            one row per constraint label: (constraint | dual)

layout=:group draws the state, the costate and the control only: one cell per group, with a legend. The path constraints and the duals have no :group cell, so they never receive the phase labels there (_phase_label_group only considers the groups the layout draws).

The constraint rows ​

The third block is built from ConstraintRows, listed by _constraint_rows(sol, model) in src/PlotCase/rows.jl. A row is one constraint label, and its two sides are drawn from the same row:

kindleft (:path)right (:dual)row exists
:paththe rows of the path constraint, g(t, x, u, v), with its boundsdual(sol, model, label)always (the right side needs row.dual)
:statethe bounded components of the state, with the bounds of the boxdual(sol, model, label)the dual is known
:controlthe bounded components of the control, with the bounds of the boxdual(sol, model, label)the dual is known

  • Order: path constraints in declaration order, then state boxes, then control boxes, in the order of the components they bound. The built model does not keep the order between kinds, and the boxes are stored by component after deduplication.

  • Aliases: the box labels are read from the aliases of the box tuple (cp[5]), not from its labels (cp[4], the first label of each component only), so a label that only re-declares a bounded component (x₂(t) ≤ 0.5, (:x2_box) after 0 ≤ x(t) ≤ 1, (:xbox)) has its row; Models.constraint_rows gives its components.

  • Not plotted: boundary constraints and variable boxes (their duals do not depend on time), and a box whose dual is unknown (the mask of has_dual).

  • One row per label: a label that bounds several components (a vector box, a multi-row path constraint) is one row whose cells are as numerous as its components.

  • The dual of a box is a single signed curve per component, zU − zL for two bounds (ct-conventions SGN2, SGN3); Solutions.dual builds it, the plot only samples it.

  • Grids: each side carries its own grid — the path grid for a path constraint, the state or control grid for a box — as every Panel does.

  • Gating: do_plot (src/PlotCase/vocabulary.jl) sets the path and dual flags from the rows: :dual needs at least one dual to draw, :path needs a path constraint, or a box row when :dual is requested. The :split branch of _build_root (src/PlotCase/build.jl) then draws each row's left side if :path is on (and, for a box, :dual too) and its right side if :dual is on and row.dual.

  • Alignment: when some row of the block has its right side and another does not, the latter gets an empty right cell (_row_unknown_dual_panel: an invisible curve on the grid of the row, so that the cell keeps the time axis of the others, and the text dual not known). Every row is then a pair and the time axes of the block are aligned. A block with no right side at all stays one column.

  • Series type: the cells of a control box are steps (:steppost) when the control is piecewise constant, the dual included (_row_seriestype): the box dual follows the control interpolation.

  • Jumps at the switching times: each side is spliced with _spliced_samples(sol, T, M, component; cols=row.rows), with the limits of the component of the row (:path_dual, :state_dual or :control_dual for the duals, stored by label in the SwitchingModel and placed on the layout by build_solution). A limit not given (NaN) is replaced by the value of the samples at the switching time, so that column is drawn with no jump (_fill_unknown_limits; for steps, the sample that holds on the interval).

  • Computed once: _build_root lists the rows once and passes them to do_plot; the path constraints and the path duals are sampled once for the whole figure (_path_samples, dual_samples) and each row takes its columns, instead of evaluating the whole stacked constraint once per label.

  • Titles and labels: the first row carries the titles and the phase labels, the last one the time label. One rule for every row, as for state | costate: the left cell carries the name and the paired right cell none (dual <label> when the right side is drawn alone). A path constraint is named by its label, a box by its component and its label, x₂ (x2_box).

pre2 = CTModels.PreModel()
CTModels.variable!(pre2, 0)
CTModels.time!(pre2; t0=0.0, tf=1.0)
CTModels.state!(pre2, 2)
CTModels.control!(pre2, 1)
CTModels.dynamics!(pre2, (r, t, x, u, v) -> (r[1] = x[2]; r[2] = u; nothing))
CTModels.objective!(pre2, :min; lagrange=(t, x, u, v) -> u^2)
CTModels.constraint!(pre2, :path; f=(r, t, x, u, v) -> (r[1] = x[1] + x[2]; nothing),
    lb=[-Inf], ub=[3.0], label=:c1)
CTModels.constraint!(pre2, :state; rg=2:2, lb=[-0.5], ub=[2.0], label=:x2_box)
CTModels.constraint!(pre2, :control; rg=1:1, lb=[-1.0], ub=[1.0], label=:u_box)

ocp2 = CTModels.build(pre2)
M = 21
T2 = collect(range(0.0, 1.0; length=M))
sol2 = CTModels.build_solution(ocp2, T2, hcat(T2, ones(M)), ones(M, 1), Float64[], zeros(M, 2);
    objective=1.0, successful=true, duals=Dict(:c1 => T2),
    state_constraints_lb_dual=zeros(M, 2), state_constraints_ub_dual=zeros(M, 2),

Keywords: build or render ​

plot(sol; kwargs...) mixes two kinds of keywords. split_plot_kwargs separates them:

  • the keywords listed in PlotCase._BUILD_KEYS (layout, control, time and the *_style keywords) shape the figure and go to build_figure;

  • every other keyword is forwarded to the renderer, which resolves it for its backend.

julia
julia> CTModels.PlotCase.split_plot_kwargs((layout=:group, state_style=(color=:red,), dpi=300))
((layout = :group, state_style = (color = :red,)), (dpi = 300,))
